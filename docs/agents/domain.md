# Domain guidance

Before exploring or designing, read the root [glossary](../../GLOSSARY.md) and
relevant [ADRs](../adr/). Use their terms in code, tests, and tickets.

Keep domain terms in the single root glossary and architectural decisions in
`docs/adr/`. Use domain-modeling when adding either. If a proposal conflicts
with an ADR, identify the conflict and explain why the decision should change.
